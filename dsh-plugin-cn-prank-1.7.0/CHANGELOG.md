## [1.7.0] — 2026-10-12

### 移除

- **矢量兜底动画整个删掉了。** 「暴打」现在只有一条路:`assets/beat.mp4`(随包发布)。跟着一起消失的东西:
  - `client.js` 的 `fatFishMarkup()` / `fatFish()` / `riceCookerMarkup()` / `riceCooker()` 四个函数、`SWEAT_SPOTS`、`BEAT_CSS`(六条 `@keyframes`,其中 `dsh-cnp-puff` 早已无人引用)、只为它们存在的 `STYLE.arena / fishWrap / cookerWrap / burst / burstRing / burstText / drop`,以及舞台里整整那个矢量分支和 `TEXT.impacts`(中英各一条)。
  - `docs/preview-vector.png`;`scripts/preview/harness.html` 的 `state=beat` 与 `state=victim` 两个分支(连画稿、`.stage .fish/.mallet/.burst/.ring/.hit/.drop` 那一组 CSS 和 `.frozen` 冻结动画);`make-previews.mjs` 里那张截图与「没有视频就画矢量」的分支。
  - 配置项 **`beatSfx`**(矢量动画的合成打击声,默认 `true`)。这是本次唯一消失的配置键。
- **`beatVideo: false` 的含义变了。** 以前是「不放视频,改用矢量动画」,现在是「不放视频,点一下立刻放行」。

### 变更

- **没有可播放的素材时一律立刻放行,不留空舞台。** 两道闸:`startBeat` 拦「点的时候就没有」(文件被删、`beatVideo: false`、路由没注册),新增的 effect 拦「点下去才发现没有」(URL 列表全部失败)。1.7.0 之前这里是「静默退回矢量动画」—— 出口还是出口,点一下照样出得去,只是不再有第二段动画。
- **合成打击音效保留,但只剩一个用途**:`beatSfxOverVideo`(默认 `false`)—— 你的视频是静音时才需要它。`beatSfxVolume` 不变。
- **`beatHits` 保留,语义收窄**成「进度条和『已敲打 N 次』按几下记账」:它不再决定任何人的惨状,也不再影响画面。
- **视频元素不再跟着命中次数重挂。** 以前每次命中都换 `key` 让 React 重挂子树(那是给 CSS 动画从头播用的),对视频来说等于把 10 秒的片子从头放九遍。现在只有换 URL 时才重挂,视频连续播放。

### 文档

- 中英两份 README 删掉「矢量兜底动画」一节、`preview-vector.png` 那张图和画稿相关的说明;`beatMs`/`beatHits`/`beatVideo`、声音一节、配置表、目录结构、兼容性一节全部按新行为改写。
- `cordis.patch.yml` 里 `banMode` 那条注释原来是错的(写着 `false` = 不显示按钮、不注册路由,而实现是按钮与状态路由都留着,只是不读盘),顺手改正。
- `verify-manifests.mjs` 相应更新:预览图清单去掉 `preview-vector.png`,把原来那句「这个仓库故意不带视频」的注释改正(它一直带着),并新增一条「没有素材时必须放行」的接线检查。

### 说明

## [1.6.1] — 2026-10-11

### 修复

- **两条 `const` 声明被切掉了前缀,两个组件一挂载就抛 `ReferenceError`。** 这一类损伤有一个共同长相:一个完整的表达式,前面那句 `const NAME =` 不见了,于是它变成一个没人读的裸表达式,而 `NAME` 成了未声明标识符。`node --check` 查不出来(裸表达式语法完全合法),而「这个标识符在文件里声明过吗」也查不出来 —— 同名变量在**另一个组件**里声明着,正好把这一处盖住。
  - `client.js` 的 `const banReady =`:「封号模式命中就弹」那条 effect 直接哑掉。**时区封锁令、封号模式命中、Claude模式复查这三条弹窗路径同时死掉** —— 表现就是「插件像是装上了,但永远不弹」,而状态灯照常工作,让人以为是设置问题。
  - `client.js` 的 `const tone =`:封号模式那颗状态灯的颜色。于是**侧边栏那颗总开关按钮从来没渲染出来过**。那为什么总开关是开着的?因为「Claude模式」的 `?timer=N` 会顺手把总闸打开 —— 用户是通过滑块间接打开它的,而按钮本身不存在。
  - 两处都存在于 1.6.0 的打包产物里:**1.6.0 从来没有真正弹过一次,侧边栏也从来没有那颗总开关**。
  - 宿主半侧一直是好的:状态接口照常返回 `on: true`、命中记录和复查间隔,只是浏览器那半边接不住。
  - 排查方式:一个按「裸表达式 + 上一行不是延续」判定的检测器。它在这份 1.6.0 产物上精确命中这 2 行,在修复后的 7 个源文件上是 0 命中 —— 也就是说这一类损伤没有第三处。

### 修复(一轮完整审计)

两轮只读审计(`client.js` 全文 + 宿主/脚本/文档一致性)查出的其余缺陷,重的在前:

- **两个会话记号在每次页面加载时被清掉。** `gateRef` 初值 `false`,而 store 的初值 `on` 也是 `false` —— 第一次轮询带回 `on: true` 时这个 effect 把它当成一次「关 → 开」的跳变,于是 `SESSION_KEY` 与 `HIT_KEY` 每次刷新都被清一次:`oncePerSession` 形同虚设(点掉那封信、刷新、又挨一次),命中去重也一起失效 —— 而「刷新不算邀请」正是这条规则当初要防的事。现在用一个 `null` 表示「还没听到过宿主的回答」,只有真正的 `false → true` 才清。
- **「连按三次 Esc」实际一到两次就放行。** 同一个计数器挂在 `keydown`/`keyup`/`keypress` 三种事件上,一次按下就涨两三次。现在只数 `keydown`(长按的 `repeat` 不算),第三次那一击也补上了 `preventDefault`/`stopImmediatePropagation` —— 放行是放行,不是把 Escape 转交给应用。
- **命中与复查到点会打断正在进行的交互。** 宿主每 10 秒盖一个新的 `hit.at`,而这两条 effect 只判「该不该弹」、不判「用户正在看什么」,于是读到一半的裁定书会被整封顶掉、敲打动画停在半途,用户还得重新点一次。现在它们只在 `phase` 是 `idle`/`over` 时拉起通知;闸门读的是 ref,因为定时器和订阅回调里的闭包 `phase` 是创建那一刻的旧值。
- **输入框把非法输入当成「清空」。** 粘贴「3分钟」「abc」或出现「1e」这类中间态时浏览器把 value 报成空串,原来的代码把它当 `0` 提交 —— 等于在用户打字的半途静默关掉复查间隔。现在 `validity.badInput` 为真时直接不提交。
- **`beatSfxVolume` 是 NaN 时敲打动画永不结束。** `Math.max(0, Math.min(1, NaN))` 仍然是 NaN,给 AudioParam 赋 NaN 会抛;抛出点在 interval 回调里 `setHitCount` 之后、收尾分支之前,于是这个 interval 永远不被清理。现在音量走 `Number.isFinite` 兜底。
- **敲打期间点出口会放行两次。** 出口的点击冒泡到 backdrop,而 backdrop 整块也是「点哪儿都跳过」,一次点击走两遍 `release()`(顺手多发一次 `?suppress=1`)。现在出口自己 `stopPropagation`。
- **`videoSoundBlocked` 放行时不复位**,同一页面里的第二封信会挂着「以静音播放」这句错误的说明。
- **`markShown()` 不分来源**:命中和复查两条路弹窗也会写掉「本会话已经弹过时区那封」的记号,可能让人永远看不到时区那封。现在只记 `mode === 'timezone'`。
- **`createSfx` 的 `AudioContext` 从不关闭**,卸载/HMR 之后每个实例都留着一条输出流。现在有 `dispose()`,组件卸载时调用。
- **扫描只数文件、不数目录。** 一棵全是目录(或全是应跳过扩展名)的树永远碰不到 `banModeMaxFiles`,一轮可以跑很久 —— 而 `?on=1` 会一直等它,表现接近卡死。现在这个上限统计的是**条目**(文件和目录一起算);队列也改用游标而不是 `shift()`(`shift()` 每次 O(n),宽目录树下退化成 O(n²))。
- **「超过 64 KB 的文件整个跳过」与文档矛盾,而且是死代码。** 文档三处都写「只读开头 64 KB」,代码却是 `size > maxBytes → 0`,后面那个 `subarray` 因此永不生效。现在改成真的截断读取(`open` + `read`,不会把整个大文件拉进内存),文档也据此改正。
- **拿不到工作区注册表时会退化成扫宿主进程的当前目录。** 在别人的机器上,那可能是 DSH 的安装目录 —— 而这与 README 的承诺(「你登记过的工作区,不是你拥有的一切」)正相反。现在返回空,也就是什么都不扫。
- **状态路由不限制 HTTP 方法**:`POST …/status?on=1` 照样切换状态,而视频路由对非 GET/HEAD 回 405。现在两条路由一致,都只接 GET/HEAD。
- **状态文档以 `Access-Control-Allow-Origin: *` 暴露 `roots`**(用户工作区的绝对路径),而客户端从不读它。删掉。
- **`scans` 字段存在却没人读**,后果是 `banMode: false` 时那颗灯一直是绿的、写着「正在扫」。现在客户端读它,把灯画成暗灰的「扫不了」。
- 清理:`TEXT_EXTENSIONS` 里两个不可达条目(`.gitignore`/`.editorconfig`,被 `dot <= 0` 先命中)删掉并写明规则;`beatVideo: false` 时不再打印那条根本不存在的路由日志。

### 变更

- **复查间隔那个控件的语义定死为「复查间隔」,不是倒计时。** 代码在 1.6.0 之后就已经改成「每隔 N 分钟确认一次系统时区,命中就再弹一次」,但同一版里的按钮文案、README 还在承诺「N 分钟后弹出封号通知」—— 一个仓库里同时写着两种行为,而两种都因为上面那个 bug 从没被谁看见过。
  - 唯一真相现在是:**被命中的是时区,不是时间**;填成 ≥1 分钟会**立刻先查一次**;填 0(或清空)取消复查但不动总开关;关掉总开关会连间隔一起清掉。
  - **宿主侧的 `dueAt` 与 `timer.remainingMs` 删掉了。** 一个会过期的到期时间戳会让侧边栏在设好 1 分钟之后自己变灰、文案自己变回「未设定」,而复查其实还在跑。状态接口现在只回 `timer: { minutes }`。
  - 侧边栏那颗灯改为跟着**分钟数**走:设了就是琥珀,不再跟着一个会到期的时刻走。
  - 宿主内部那个也叫 `timer` 的扫描句柄改名 `scanner`:同一个状态对象上挂着两个 `timer`,是那种「读到一半得停下来想一想到底是哪一个」的名字。
  - 输入框的本地值不再被轮询覆盖:落盘有防抖窗口,提交后还留 2 秒回声保护区 —— 否则一次 5 秒轮询会拿宿主的旧值把用户刚打完的数字擦掉。
  - **代价说清楚**:它不再承诺「一分钟后会发生什么」。想要那种「到点必弹」的倒计时,得再加一个字段,而不是把两种语义塞进同一个数字。

- **「复查间隔」那封信顶上的窄带删掉了。** 它原来写的是「中国鱼能飞」。窄带存在的唯一理由是报出**「哪个文件、多少个字」**,而这条路上没有文件可报,于是那句话只是一句占着版面、什么也不说的玩笑。Claude体验模式那条窄带留着,因为它真的在回答这个问题。
  - **代价**:这条路弹出来的信现在和时区那封长得完全一样,你没法从画面上分辨是谁叫来的 —— 状态接口里的 `timer.minutes` 是唯一痕迹。
  - `TEXT` 里中英两份 `timerStrip` 一起删了,没有留下没人读的字段。

### 界面

  - 「Claude模式」这几个字从界面上消失(名字让给了上面那颗按钮),`TEXT` 里的 `timerLabel`、`timerEvery` 与 `STYLE.timerSlider`/`timerValue` 一并删掉,换成 `timerPrefix` + `timerInput`。
  - 0–60,0 = 关;空框里是灰色的「关」占位符 —— 空和 0 本来就是同一件事。
  - 回车即落盘,不用先去点别处;打字仍然防抖(`TIMER_COMMIT_MS`,600 毫秒),否则打「12」会先提交一个「1」。
  - 提交后 `TIMER_ECHO_GUARD_MS`(2 秒)内不信宿主的回声,理由见上面那条。

- 这是**修复 + 澄清**版本,没有新功能。

- 这一轮审计里**没有改**、但值得知道的几处:①`banModeIntervalMs` 的首轮扫描会阻塞 `?on=1` 的响应(刻意的,避免状态灯闪一下);②视频路由每次请求同步 `readFileSync` 整个 1.9 MB 文件;③「合法但不可满足」的 Range(如 `bytes=5-1`)回 200 整包而不是 416;④侧边栏收成 56px 轨道时数字框不渲染,折叠状态下设不了间隔;⑤逃生通道开着时侧边栏「看起来在工作」(见上文,已写进 README);⑥`phase` 一旦离开 `idle` 就永不回头,所以运行时撤掉逃生通道必须刷新页面才生效。

## [1.6.0] — 2026-10-11

### 裁定书重写(14 条「对外 / 内心OS」)

- **不再读设备指纹。** 上一版的证据是「引用一个真数字 + 一个离谱结论」;这一版换成 14 种嘴脸,每条一句**对外口径**、一句**内心 OS**。笑点从「数据真、结论假」挪到了「官话真、动机假」—— 后者更难被证伪,因为它说的不是你的电脑,是你。

### 修复

- **扫描会阻塞整个 Host 事件循环。** `readdirSync`/`statSync`/`readFileSync` 走完 400 个文件,期间所有活着的 agent turn 一起卡住。改成 `node:fs/promises`,并在上一轮没跑完时不再起新一轮(`inFlight`)。

### 变更

- **`oncePerSession` 默认改成 `true`。** 原来是 `false`(每次刷新都弹),结果点掉之后随手一刷新又挨一次 —— 那不像恶作剧,像卸载不掉。现在同一个浏览器会话只弹一次,换会话才重来;想要原来那种「每次都弹」把它设回 `false` 即可。
- **`package.json` 去掉 `dsh.client.inject`。** 那一行是整个清单里唯一把插件绑死在某个 DSH 包布局上的东西:如果对方的 DSH 版本里没有 `@deepseek-ai/dsh-client-ui-renderer` 这个条目,Client 半侧可能永远不激活,表现是通知和侧边栏按钮都不出现、也不报错。而本插件用的两个座位(`shell.overlay`、`sidebar.footer.action`)都是 **shell 自己声明的**,加载顺序在第三方 bundle 之前 —— 那个字段本来要买的顺序保证是白送的。
  - **代价我要说清楚:这一条我没能实测。** 去掉 `inject` 之后要重启 DSH 才会重新扫清单,而重启会杀掉当前会话。如果你重启后通知或侧边栏按钮不见了,把 `"inject": ["@deepseek-ai/dsh-client-ui-renderer"]` 加回 `dsh.client` 即可回滚。
- 状态路由由 `/dsh-cn-prank/ban` 改名 `/dsh-cn-prank/status` —— 它现在同时承载总开关状态和封号模式。客户端内的 `createBanStore`/`useBanState`/`createBanButton` 相应改名,注入配置里的 `banUrls` 改为 `statusUrls`。
- 这条路由只要插件还开着就注册:开关关着的时候页面更需要知道这件事,否则它无从判断该不该闭嘴。

### 侧边栏按钮升级为总开关(默认「关」)

- **关着就是什么都不弹** —— 连时区那封也不弹;按一下才启动,时区那封和封号模式的扫描一起进入待命;再按一下全部静音。
  - **代价写在明处:插件不再「自动整人」。** 装上不按,它永远不会出现。这是「关闭就不会有任何弹窗」在逻辑上的必然结果 —— 「装上就自动弹」和「关着就什么都不弹」不能同时成立,两者只能选一个。
  - 布防那条 effect 在总开关关着时**不设 `phase`**,只是不布防。若那时设成 `'off'`,开关再打开时 `phase !== 'idle'` 会让布防永远回不来。
  - 状态接口的 `available` 跟着 `enabled` 走,不再跟着 `banMode` 走 —— 它是总闸,不是某个功能的可用性。
- **`banMode: false` 现在真的不读盘。** 按钮仍然在(它是总开关),但扫描能力在那时已经关掉;以前扫描会绕过这个开关。
- **封号模式接进会话记忆**:`hit.at` 弹过一次就写进 `sessionStorage`,同一个命中在一次浏览器会话里只弹一次,刷新不再重弹,新命中(新时间戳)照常弹。
- **按下总开关会清掉两个会话记号。** 按按钮是一次明确的邀请,刷新页面不是 —— 清记号的时机只能是「关 → 开」那个跳变。没有这一条,第二次按按钮会因为「本会话已弹过」而毫无反应。

### 修复

- **`enabled: false` 以前拿不掉侧边栏那颗按钮。** `apply(ctx)` 无条件注册 `sidebar.footer.action`,而 `createStatusButton` 只检查 `available`(那时等于 `banMode`),与 `enabled` 无关 —— 结果配置文件里明确写了关闭,按钮还在,点下去仍然开始扫工作区、仍然弹通知。说好了不工作却仍在读别人的磁盘,这是这份清单里最不该有的那种 bug。现在组件直接看 `config.enabled === false`。
- **`oncePerSession` 默认改成 `true`。**

## [1.5.0] — 2026-10-11

### 修复

- **视频之前是没声音的,因为插件把它 `muted` 掉了。** `assets/beat.mp4` 一直带着一条 AAC 音轨,而 `muted` 只是浏览器「不许带声自动播放」那条规矩的入场券 —— 而最省事的写法是永远静音。现在改成**先带声试**:点「暴打」本身就是一次用户手势,通常足以放行;只有在真的被拒时才退回静音播放一次,并在舞台底部说明原因。**画面不会因为声音被拦而停住**,这是这一段里唯一真正的失败姿态。
- 新增 `beatVolume`(默认 `0.9`)。音轨音量过去没有旋钮,因为音轨从未播过。

### 新增

- **合成打击音效**,给矢量兜底动画用 —— 它此前没有任何声源。一记「平底锅砸在毛绒玩具上」= 一小段带通白噪声(「啪」)+ 一个快速下滑的低频正弦(「咚」),各走一条包络,**不带任何音频文件**:仓库不用多出几百 KB 采样,也不用赌浏览器支持哪种格式。每一击的音高在 780–1400 Hz 之间随机,九下完全同频会听起来像机器。
- **两个分开的开关**,因为两种情况的正确答案相反:`beatSfx`(矢量动画打击声,默认**开**)、`beatSfxOverVideo`(在视频之上再叠一层,默认**关** —— 视频自带音频,叠了只会糊)、`beatSfxVolume`(默认 `0.5`)。视频是静音的话,`beatSfxOverVideo: true` 就是那个开关。
- `AudioContext` 在**点「暴打」的那一刻**创建并 `resume`(`sfx.warm()`),不是在页面加载时 —— 浏览器会把非手势创建的上下文挂成 `suspended`,把第一声吞掉。
- 舞台底部在被拒静音时显示 `beatSoundBlocked` 文案,而不是让用户对着一个没声音的动画猜。

### 说明

- 音效是合成的,不是采样:它不会有采样那样的辨识度,所以视频有原声时默认不叠。这条取舍写在 README 的「声音」一节里。
- 探查过程记录:我一度以为那条音轨是空的,但无头浏览器没有音频设备,`new AudioContext()` 会挂住、`decodeAudioData` 也不落地 —— 所以那个结论无法在本地证伪。改成按容器事实处理(MP4 里确实有一条 `soun` 轨),并让「带声被拒」成为一条正确的降级路径,而不是一条假设。

- **封锁层**:注册在 `shell.overlay` 座位,`position: fixed` 覆盖整个框架,`z-index: 9000`,并显式收回指针事件(该座位本身是 click-through 的)。
- **键盘封锁**:`window` 捕获阶段吞掉 `keydown`/`keyup`/`keypress` 并 `stopImmediatePropagation`,官方快捷键在封锁期间全部失效;鼠标不受影响。
- **左下「原因」**:真读一遍本机设备指纹(核心数、屏幕与视口、像素比、WebGL 显卡型号、语言、时区、触控点、堆上限、电池、`userAgentData` 高熵字段),逐行念成扫描日志后给出裁定书;18 条中文模板、12 条英文模板,证据句引用真数据。
- **右下「暴打」**:立即放行,审计过程中同样可用。
- **裁定书编号共用**:扫描日志与裁定书打印同一个 `TS-xxxxxxxx-xxxx-xxxx` 编号。
- **配置通道**:Host 半侧用 `webserver/index-inject` 的结构化 `global` 行把行配置发布成 `window.__DSH_CN_PRANK__`,Web 与桌面壳两种形态都生效。
- **可调项**:`enabled` / `timezones` / `delayMs` / `oncePerSession` / `blockKeyboard` / `scanMs` / `reasonAutoCloseMs`。
- **五条逃生通道**:`config.enabled: false`、`window.__DSH_CN_PRANK_OFF__`、`localStorage['dsh-cn-prank:off']`、`?no-prank=1`,以及封锁期间连按三次 `Esc`。
- **内联图片**:通知图片以 data URI 内联进 `client.js`,由 `scripts/build-notice.mjs` 从 `assets/notice.webp`(55 KB WebP)生成,`--check` 模式供 CI 校验两者一致。
- **双语文案**:界面文案与裁定书模板各有中英两套,语言取 `ctx.get('locale')`,拿不到退回 `navigator.language`。
- **自检**:`npm run check` 解析四个文件,`npm run verify` 校验清单、补丁行、exports、locale、内联图片与 Host/Client 的全局名一致;`.github/workflows/ci.yml` 跑同一套,无需安装依赖。
- **零依赖**:不 import 任何 `@deepseek-ai/*` 包,不需要构建步骤。
- **README 预览图**:`docs/preview-lockdown.png` 与 `docs/preview-verdict.png`,由 `scripts/make-previews.py` 生成(示意图,不是截图)。
